Codex for Finance｜可复制 Prompt Pack

使用方式

以下 Prompt 已按课程模拟文件设计，可在 Codex Desktop 中直接复制。运行前请确认当前 Workspace 就是解压后的 codex-labs 课程材料文件夹，且所有输入均为课程模拟数据。

通用规则：

  • 首次执行先使用“只读检查”，确认目录与输入。
  • 默认不修改源文件，成果写入新的 outputs/ 目录。
  • 缺失信息写为“待确认”，不得猜测或补造业务事实。
  • 涉及飞书写入、Git push、发布、发送、覆盖、删除或批量修改时，必须先展示影响范围并等待明确确认。
  • 关键数字应注明来源文件、字段、期间、单位和计算口径。

00｜开场：只读检查 Workspace

请先只读检查当前 Workspace，不要修改任何文件。

目标：确认这里是否具备完成“2026 年 6 月月度经营复盘”所需的模拟材料。

请完成：
1. 列出当前 Workspace 中的全部文件；
2. 用一句话说明每个文件的用途；
3. 标记无法读取、字段不清或可能存在口径冲突的文件；
4. 说明你计划使用哪些 Skill 或工具；
5. 给出不超过 6 步的执行计划和验收标准。

限制：

- 不访问目录以外的业务文件；
- 不推测缺失数据；
- 不执行任何外部写操作。

01｜第一次跟做：经营指标摘要

目标：把 `01-operating-metrics.csv` 整理成一页中文经营指标摘要，供管理层在 3 分钟内阅读。

工作方式：
1. 先检查 CSV 的编码、字段、期间、单位、空值和重复记录；
2. 识别核心 KPI 的本期值、目标值、同比或环比信息；
3. 计算时展示口径，不要仅给最终数字；
4. 提炼 3 条最重要结论，每条结论必须标注来源字段；
5. 最后重新读取源文件，逐项复核输出数字。

限制：
- 不修改源 CSV；
- 缺失信息标记为“待确认”，不要猜测；
- 不使用真实公司或个人名称；
- 不进行外部写入。

交付物：
- 新建 `outputs/01_经营指标摘要.md`；
- 包含“核心指标、主要变化、风险信号、待确认事项、数据说明”五部分。

验收标准：
- 所有数字带单位；
- 所有结论可追溯到源文件字段；
- 总结不超过 800 个中文字符；
- 最后一节列出自检结果。

02｜结果复核：给每条结论补证据

请复核你刚生成的 `outputs/01_经营指标摘要.md`。

逐条检查：
1. 数字是否与 `01-operating-metrics.csv` 一致；
2. 单位、期间、正负号和百分比是否正确；
3. 每条结论是否能指出来源字段或记录；
4. 是否把相关性误写成因果关系；
5. 是否存在缺少证据但语气过于确定的表述。

发现问题时直接修正输出文件，并在文末新增“修订记录”，用表格列出原内容、问题、修订内容和证据。没有发现问题也要明确写出检查范围，不要只回复“已确认无误”。

03｜贯穿案例：月度经营复盘主 Agent 完整版

目标：使用课程模拟材料，完成“2026 年 6 月月度经营复盘”，形成可供管理层审阅的中文材料。

输入范围仅限：

- `02-budget-variance.csv`
- `03-contract-risk.md`
- `04-tax-items.md`
- `05-admin-procurement.md`
- `06-management-report-template.md`

请按以下阶段工作：

阶段 A｜只读观察
1. 确认六个文件均可读取；
2. 输出字段、期间、币种、单位和口径检查；
3. 列出缺失、重复、冲突和异常值；
4. 先给执行计划，不要立刻写报告。

阶段 B｜分析
1. 汇总核心 KPI、预算差异和趋势；
2. 将合同、税务、行政事项与经营指标交叉关联；
3. 区分“数据事实、合理推断、待确认事项”；
4. 对每条重点结论记录来源文件和字段或段落；
5. 提炼不超过 5 条管理层行动建议，每条建议包含 Owner 角色、优先级和建议期限。

阶段 C｜交付
请创建 `outputs/monthly-review/`，输出：
- `管理层摘要.md`：遵循 `06-management-report-template.md`；
- `指标与差异明细.csv`：保留数据来源列；
- `风险与行动项.csv`：包含类别、事项、证据、风险等级、Owner、期限建议、状态；
- `数据质量与待确认事项.md`；
- `执行日志.md`：记录读取文件、计算与验证动作，不记录任何密钥或个人路径。

阶段 D｜验证
1. 重新读取两个 CSV 与全部输出；
2. 检查总计、单位、期间和来源引用；
3. 检查是否意外修改源文件；
4. 将验证结果写入 `outputs/monthly-review/验证报告.md`；
5. 若验证失败，不要掩盖，标记失败项与修复建议。

限制：
- 全部材料均为模拟数据；
- 不访问外部系统；
- 不修改输入文件；
- 不编造缺失原因；
- 不把风险建议写成最终法律、税务或审批结论。

现在先完成阶段 A，并等待我确认计划后再继续。

05｜Subagents：五视角并行复盘

请使用 Subagents 并行完成月度经营复盘。先检查当前环境是否支持 Subagents；支持时再执行，不支持则明确说明并提供顺序执行 fallback，不要假装并行。

所有 Agent 共同规则：
- 输入只限编号 01 至 06 的模拟文件；
- 只读输入，不修改源文件，不访问外部系统；
- 所有发现使用统一字段：`发现｜证据｜影响｜风险等级｜建议｜待确认`；
- 证据必须注明文件名与字段或段落；
- 不确定就写“待确认”，不得编造。

请创建五个独立 Subagents：

1. 法务审阅 Agent
   - 重点：合同主体、授权、付款、履约、违约、数据与知识产权风险；
   - 主要读取：`03-contract-risk.md`，必要时交叉读取指标和预算文件。

2. 行政审阅 Agent
   - 重点：采购材料、供应商、预算、交付期限、执行责任；
   - 主要读取：`05-admin-procurement.md` 与预算文件。

3. 财务审阅 Agent
   - 重点：收入、成本、费用、预算差异、现金与勾稽关系；
   - 主要读取：两个 CSV。

4. 税务审阅 Agent
   - 重点：主体、期间、税率、发票、税务口径和待复核事项；
   - 主要读取：`04-tax-items.md`，必要时交叉读取两个 CSV。

5. 经营分析 Agent
   - 重点：KPI 表现、趋势、驱动因素、业务影响和管理动作；
   - 读取全部文件，但不代替其他专业 Agent 作最终判断。

主 Agent 的责任：
1. 等待并回收全部结果；
2. 标记失败或未完成的 Subagent；
3. 合并重复事项，建立冲突清单，不要随意二选一；
4. 重新复核所有关键数字；
5. 生成 `outputs/subagents/跨部门复盘.md` 与 `outputs/subagents/冲突与待确认.csv`；
6. 在文末列出每个 Subagent 的任务状态和输出摘要。

执行前先展示：任务拆分、每个 Agent 的输入范围、预计交付物和主 Agent 的验收标准；得到我确认后再启动。
