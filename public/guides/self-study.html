Codex for Finance｜课后自学路径

学习目标

自学路径不是继续堆功能，而是把现场的一次成功操作变成稳定、可复用、可审阅的工作方式。建议按 Level 1—4 顺序完成；每一级都要留下成果和验证记录。

学习地图

Level 建议时间 核心能力 完成标志
1｜安全上手 45 分钟 Task、Workspace、Prompt、Diff、验证 独立生成并复核一个本地成果
2｜岗位提效 2 小时 多文件、Office、岗位场景、Skills 完成一个本部门模拟任务
3｜工作流升级 3 小时 Subagents、Superpowers、Skill creation、AGENTS.md 生成并测试一个可复用 Skill 草稿
4｜连接与交付 3—4 小时 飞书 CLI、Sites、Automation、Git / PR 完成一个测试环境端到端闭环

Level 1｜安全上手

目标

  • 独立新建 Task、选择正确 Workspace。
  • 使用 GOALS 结构写出可执行 Prompt。
  • 查看工具调用、Terminal、Diff 和输出文件。
  • 对关键数字和结论完成来源复核。

练习 1：单文件摘要

输入

  • 01-operating-metrics.csv

动作

  1. 运行 Prompt Pack 的“01｜第一次跟做”。
  2. 运行“02｜结果复核”。
  3. 手工抽查至少 3 个数字。

完成标准

  • 输出文件没有覆盖源文件。
  • 数字带期间和单位。
  • 每条重点结论有来源。
  • 修订记录能说明发现并修正了什么。

练习 2：学会纠偏

选择输出中的一处不足，不使用“优化一下”，而是明确指出：

  • 哪一段有问题；
  • 缺少什么证据；
  • 希望改成什么结构；
  • 修改后如何验证。

示例

“主要变化”第二条只有结论，没有来源。请补充来源文件和字段，并把事实与原因推断分开。修改后重新核对数字与单位，只改这一节。

Level 1 测试

不看教程，独立完成：

选择 Workspace → 只读检查 → 生成新文件 → 查看 Diff
→ 核对一个数字 → 要求 Codex 输出验收证据

全部完成后再进入 Level 2。

Level 2｜岗位提效

目标

  • 让 Codex 读取多个文件并建立证据链。
  • 知道何时调用现有 Skill。
  • 完成本部门一个模拟场景。

公共练习：多文件月度经营复盘

  1. 运行 Prompt Pack 的“03｜月度经营复盘主 Agent 完整版”。
  2. 检查阶段 A 的口径风险后再确认执行。
  3. 使用“32｜最终验收”收口。

完成标准

  • 两个 CSV 与四个 Markdown 均被读取。
  • 数据事实、推断与待确认事项分开。
  • 至少产生一个管理层摘要和一个结构化 CSV。
  • 验证报告包含失败项，不只写“通过”。

部门学习分支

法务

使用 Prompt Pack 的“26｜法务合同风险审阅”。

进阶挑战：再创建三个角色分别检查付款与违约、数据与保密、知识产权与终止，比较三者是否遗漏或重复。

人工边界

  • Codex 输出为风险识别与修订草稿，不替代最终法律判断。
  • 缺失条款不得自动补为“已约定”。

行政

使用“27｜行政采购复盘”。

进阶挑战：将风险与行动项转换为测试 Base 可导入 JSON，并设计去重键。

人工边界

  • 不自动评价或联系真实供应商。
  • 不自动提交采购、付款或审批。

财务

使用“28｜财务预算差异”。

进阶挑战：要求 Codex 为每个差异列出公式、输入记录和勾稽结果，再生成管理层图表。

人工边界

  • 预算版本、币种、期间、正负号由财务 Owner 确认。
  • 原因分析没有证据时只能标为假设。

税务

使用“29｜税务事项核对”。

进阶挑战：制作一张“字段完整性规则表”，让 Codex 只标记异常，不自动作最终税务处理。

人工边界

  • 不让 Codex 猜测税率、主体或申报口径。
  • 高风险事项交由税务负责人复核。

经营分析

使用“30｜经营分析管理层摘要”。

进阶挑战：把结论拆成“指标 → 驱动 → 影响 → 行动”，要求每条链路保留来源。

人工边界

  • 区分相关性与因果关系。
  • 行动建议必须有 Owner、期限与后续指标。

找 Skill 的标准路径

描述任务 → 在内部 Skill 市场搜索 → 阅读说明与权限
→ 内部没有匹配项 → 学习网络课程 → GitHub 搜索
→ 让 Codex 只读评估 → 小样本测试 → 再决定是否安装

首选入口

  • 瓶子星球 Skill 市场
  • Finance Learning Hub（内部学习中心）：GitHub 与科学上网课程；入口不对外公开，见内部群公告

评估练习

  1. 在内部市场选择一个候选 Skill。
  2. 运行 Prompt Pack 的“10｜第三方 Skill 安全评估候选仓库”或对应内部评估模板。
  3. 不安装，只提交一页风险报告。

Level 2 测试

  • 完成本部门模拟任务。
  • 输出含来源证据与待确认事项。
  • 能解释为什么选择或不选择某个 Skill。
  • 能指出至少一个必须保留人工判断的节点。

Level 3｜工作流升级

目标

  • 使用 Subagents 并行处理独立子任务。
  • 使用 Superpowers 的成熟 workflow 澄清和规划复杂任务。
  • 将稳定重复流程封装为 Skill 草稿。
  • 使用 AGENTS.md 固化团队长期规则。

练习 1：五角色 Subagents

运行“05｜Subagents：五视角并行复盘”。

重点观察：

  • 每个 Subagent 是否只处理被分配的范围。
  • 是否使用统一输出结构。
  • 主 Agent 是否等待全部结果。
  • 冲突是否被显式列出，而不是被悄悄覆盖。
  • 最终数字是否由主 Agent 重新勾稽。

完成标准

  • 五个角色状态可见。
  • 至少一条跨部门冲突被正确标记。
  • 有失败处理或重试策略。
  • 没有多个 Agent 同时覆盖同一输出文件。

练习 2：Superpowers 需求与计划

运行“07｜Superpowers：先做需求访谈再制定计划”。

重点学习：

  • 先确认当前安装状态和实际 Skill 名称。
  • 一次只回答一个关键问题。
  • 比较不同方案的取舍。
  • 选择方案后再进入实施计划。

完成标准

  • 有清晰的问题记录。
  • 至少比较两个方案。
  • 实施计划包含验证和回退。
  • 没有因为调用第三方 workflow 而跳过业务口径确认。

练习 3：创建自己的第一个 Skill

运行“13｜从自己的重复工作出发”。

先用下面的筛选表决定是否值得封装：

判断 是 否
每月或每周重复发生 适合继续评估 可能只需一次 Prompt
输入与输出相对稳定 适合 先整理 SOP
规则能写清楚 适合 先访谈业务 Owner
结果可用 checklist 验证 适合 暂不自动化
风险可设置人工确认点 适合 降级为只读辅助

Skill 草稿完成标准

  • SKILL.md 有触发条件与明确不适用场景。
  • 输入、步骤、输出和验证清楚。
  • 外部写操作有人工确认。
  • 有最小测试案例。
  • 不包含密钥和真实业务数据。
  • 有 Owner 与版本占位符。

练习 4：AGENTS.md

运行“23｜AGENTS.md：为财运中心写长期规则草稿”。

把规则分成两类：

  • 长期规则：语言、安全、目录、验证、发布门槛。
  • 单次 Prompt：本月期间、当前文件、临时输出格式。

不要直接覆盖现有 AGENTS.md；先生成 preview，人工审阅后再合并。

Level 3 测试

  • 能解释 Subagent 与“多角色顺序分析”的差异。
  • 能说明 Superpowers 是第三方项目。
  • 完成一个 Skill 草稿和一次最小测试。
  • 完成一份长期规则草稿，没有混入密钥和临时信息。

Level 4｜连接与交付

目标

  • 将成果安全写入飞书测试空间。
  • 将数据结果生成可运行网站。
  • 设计带人工门槛的 Automation。
  • 通过 Git / Pull Request 完成团队审阅。

练习 1：飞书文档闭环

课前按指定飞书社区教程完成连接。教程可能更新，使用当前版本实际提示。

执行顺序：

  1. “16｜飞书文档：写入前预览”。
  2. 确认目标为测试空间。
  3. “17｜创建月度经营复盘文档”。
  4. “18｜读取并总结”。
  5. 比较写前本地摘要与写后读取结果。

完成标准

  • 写入前显示目标、内容、覆盖、通知与权限影响。
  • 写入对象明确标注为测试。
  • 写后重新读取并核对。
  • 没有改变权限或通知真实成员。

练习 2：飞书 Base 闭环

执行顺序：

  1. “19｜Base 模拟数据写入预演”。
  2. 人工确认字段映射和去重键。
  3. “20｜确认后写入测试表”。
  4. 抽样检查三条记录，确认没有重复。

完成标准

  • 预演数量与 JSON 记录数一致。
  • 字段类型匹配。
  • 重复执行不会产生重复记录，或会明确停止。
  • 部分失败有结构化日志。

练习 3：中文交互网页

运行“14｜Sites：生成管理层中文交互网页”，再运行“15｜网页 QA”。

内容验收

  • 所有用户可见内容与导航为中文。
  • KPI 与本地复盘结果一致。
  • 风险和行动项保留来源。

体验验收

  • 每个主要章节有有意义的 GSAP 滚动动效。
  • 动效不遮挡文字和复制按钮。
  • reduced motion 模式可完整阅读。
  • 键盘焦点、移动端和错误状态正常。

工程验收

  • 本地 server 可启动并打开预览。
  • build 与 test 通过。
  • GitHub Pages 项目子路径下资源正常。
  • 不包含真实业务数据、个人路径或 Token。

练习 4：设计 Automation

运行“24｜Automation：设计但不创建定时复盘”。

先评审设计，再决定是否在测试环境创建。生产化前必须明确：

  • 数据到齐判断。
  • 超时、失败与重试。
  • 幂等性与重复输出。
  • 人工复核和审批点。
  • 失败告警与停用条件。

练习 5：Git 与 Pull Request

运行“25｜Git / Pull Request：发布前审阅计划”。

学习目标不是记命令，而是理解：

  • Diff 让修改可见。
  • Commit 记录一组有意义的修改。
  • Push 把修改发送到远端。
  • Pull Request 让团队审阅、讨论与检查通过后再合并。
  • Worktree 让多个任务或 Agent 在隔离目录中工作，避免互相覆盖。

完成标准

  • 发布前检查中没有密钥和真实数据。
  • build 与 test 证据可见。
  • Pull Request 描述包含范围、验证、风险与截图。
  • 没有绕过审阅直接发布高风险内容。

Capstone｜月度经营复盘端到端挑战

任务

从模拟数据开始，完成以下闭环：

只读检查 Workspace
→ 主 Agent 数据质量检查
→ 五个 Subagents 并行审阅
→ 主 Agent 勾稽与冲突处理
→ 生成管理层摘要与行动表
→ 生成中文交互网页
→ 写入飞书测试文档与测试 Base
→ 输出最终验收报告

交付物

  • 本地 Markdown 管理层摘要。
  • 风险与行动项 CSV。
  • 数据质量与验证报告。
  • 中文管理层交互网页。
  • 飞书测试文档链接。
  • 飞书测试 Base 执行报告。
  • 一份可复现说明。

通过标准

维度 通过条件
数据 关键数字与源文件一致，口径和单位明确
证据 重要结论可追溯，推断与事实分开
安全 无密钥、个人路径和真实数据；写操作有确认
协作 Subagents 职责清楚，冲突被主 Agent 处理
交付 本地、网页和飞书成果均可打开
验证 有实际检查记录，不以“文件存在”代替通过
复现 另一位学员能够按说明重新执行

推荐学习节奏

第 1 周：建立正确习惯

  • Day 1：Level 1 单文件练习。
  • Day 2：本部门 Prompt。
  • Day 3：多文件复盘。
  • Day 4：选择并评估一个 Skill。
  • Day 5：整理一个自己的高频任务。

第 2 周：形成工作流

  • Day 1：Subagents 并行复盘。
  • Day 2：Superpowers 需求访谈与计划。
  • Day 3：创建 Skill 草稿。
  • Day 4：飞书测试闭环。
  • Day 5：交互网页或 Automation 设计。

团队共创建议

每个部门选择一名 Owner，建立一张 Skill 候选清单：

字段 说明
场景名称 业务语言描述，不用技术名
使用频率 每日 / 每周 / 每月 / 临时
当前耗时 人工耗时与等待时间
输入 文件、系统和责任人
输出 谁使用、以什么格式使用
稳定规则 可以明确表达和验证的规则
人工判断 不允许 Codex 自动决定的节点
数据等级 模拟、脱敏、内部或禁止使用
建议形态 Prompt / Skill / Automation / 普通 SOP
Owner 业务维护人

优先选择“高频、规则清楚、数据低风险、结果可验证”的场景，不从最复杂、最敏感的生产流程开始。

自学过程中遇到问题

使用下面的诊断 Prompt，不要反复盲目重试：

请停止继续修改，先只读诊断当前任务。
告诉我最后成功步骤、报错原文、部分输出、重复写入风险、最小重试范围和一个 fallback。在我确认前不要重试、删除或覆盖文件。

记录以下信息：设备与系统、Codex 版本、发生时间、任务目标、错误原文、已尝试动作和脱敏截图。不要提交密钥、Token、真实文件或个人路径。

结业自评

当你能独立回答以下问题，说明已具备稳定使用基础：

  • 我能把业务需求写成目标、输入、动作、限制和验收标准。
  • 我知道复杂任务为什么先 Plan。
  • 我能查看工具调用、Diff、日志和输出文件。
  • 我知道何时用 Skill、Subagent、MCP、Automation 或普通 Prompt。
  • 我能安全评估第三方 Skill，而不是直接安装。
  • 我能让关键结论保留来源，并处理不确定项。
  • 我知道飞书写入、Git push 和网站发布前需要检查什么。
  • 我能把一次成功任务沉淀为模板、AGENTS.md 或 Skill 草稿。
