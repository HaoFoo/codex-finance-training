# 月度经营复盘｜可复制练习 Prompts

> 使用方法：先把整个 `monthly-review` 文件夹下载到本地，并在 Codex 中将该文件夹设为 workspace。每次只复制一个 prompt。所有数据均为虚构培训数据。

## Prompt 1｜基础汇总：5 分钟读懂经营表现

```text
请读取当前 workspace 中的全部 CSV 和 Markdown 文件，完成 2026 年 6 月经营复盘快速摘要。

要求：
1. 先列出你实际读取到的文件；没有读取到的文件不要假装读取。
2. 用“结果、原因、风险、行动”四段式输出，每段不超过 5 条。
3. 所有数字必须注明来源文件；金额统一使用“万元”。
4. 校验：毛利额 - 期间费用 = 经营利润；行政采购明细合计 = 行政采购实际金额。
5. 如果发现数据冲突，单列“数据疑点”，不要自行改数。
6. 最后给出 3 条按优先级排序的管理层关注事项。
```

**预期结果：**识别收入差 70 万元、经营利润差 54.5 万元、应收账款及合同验收风险，并完成两项勾稽检查。

## Prompt 2｜Superpowers：先拆问题再制定复盘路径

```text
请调用 Superpowers 的 brainstorming Skill，帮我设计一次“2026 年 6 月月度经营复盘”的分析路径。

输入材料就是当前 workspace 的文件。请先确认汇报对象、核心决策和证据边界，再提出 2 个分析方案，并推荐其中 1 个。方案至少覆盖：经营指标、预算差异、合同、税务、行政采购、飞书行动台账。

我确认方案后，再调用 Superpowers 的 writing-plans Skill，把推荐方案转换为可执行 checklist。每一步要写清：输入文件、分析动作、输出、质量检查。不得改动原始数据。
```

**演示提醒：**此 prompt 会在方案确认处暂停一次，这是 Superpowers workflow 的正常行为。

## Prompt 3｜五个 Subagents 并行分析

```text
请调用 Superpowers 中用于 parallel agents / dispatching parallel agents 的 Skill，并启动 5 个独立 Subagents 并行分析当前 workspace 的月度经营复盘材料：

- 法务 Subagent：重点读取 03-contract-risk.md，识别条款、验收、续约、回款风险。
- 行政 Subagent：重点读取 05-admin-procurement.md，分析预算、流程、采购动作。
- 财务 Subagent：重点读取 01-operating-metrics.csv 和 02-budget-variance.csv，完成利润勾稽、预算差异、现金及应收分析。
- 税务 Subagent：重点读取 04-tax-items.md，识别税会差异、凭证链条和时间节点。
- 经营分析 Subagent：读取全部材料，提炼业务驱动、趋势和管理层决策项。

统一要求：
1. 每个 Subagent 输出“发现、证据、金额影响、建议动作、待确认项”，所有事实附来源文件或事项编号。
2. 不得假设文件外的信息；缺失信息写“待确认”。
3. Subagents 完成后，由主 Agent 汇总，去重并识别跨团队依赖。
4. 最终输出一张行动表：优先级、事项编号、Owner 角色、截止日期、验收证据。
5. 最后说明实际启动了几个 Subagents；若当前环境无法启动，明确说明并停止，不要伪装成并行执行。
```

**预期结果：**看到 5 个独立分析任务及统一整合结果，至少识别合同 `CT-2026-041` 与财务、税务之间的依赖。

## Prompt 4｜生成管理层汇报

```text
请读取当前 workspace 的所有模拟材料，并严格按照 06-management-report-template.md 的结构生成一份完整管理层汇报。

输出文件：output/2026-06-management-review.md

执行要求：
1. 只使用源文件中存在的事实和数字；缺少的信息写“待确认”。
2. 完成模板中列出的全部勾稽检查。
3. 一页结论不超过 5 条，每条采用“结论 + 数字 + 业务含义”。
4. 跨团队风险必须包含事项编号、来源、Owner、截止日期和验收证据。
5. “需要管理层决策”只保留真正需要取舍或授权的事项，不把普通待办写成决策。
6. 写完后做一次 reviewer pass：逐项检查数字一致性、事实来源、行动是否可验收，并在文末附 QA 结果。
```

**验收数字：**营业收入 1,280；毛利额 384；期间费用 250；经营利润 134；经营利润较预算少 54.5，单位均为万元。

## Prompt 5｜生成中文交互式经营看板

```text
请基于当前 workspace 的月度经营复盘材料，生成一个可在本地浏览器打开的中文交互式网页。

请先调用 Superpowers 的 brainstorming Skill，快速确定信息层级与视觉叙事；不需要等待我选择，直接采用你推荐的方案继续实现。

输出目录：output/monthly-review-site/

网页要求：
1. 首页展示营业收入、毛利率、经营利润、现金流入、应收账款 5 个核心 KPI。
2. 包含预算差异瀑布或条形图、风险矩阵、跨团队行动台账和来源说明。
3. 点击风险事项可展开证据、Owner、截止日期和建议动作。
4. 全部用户界面与说明使用中文；Codex、GSAP 等产品名可保留英文。
5. 风格为明亮银白、玻璃质感、财务绿色高光；使用 GSAP ScrollTrigger 制作克制的滚动动效，并支持 prefers-reduced-motion。
6. 不得通过网络上传数据；不要嵌入真实品牌、API key 或个人信息。
7. 提供清晰的 README，说明如何预览；完成后自行运行本地检查并给出预览地址。
```

**预期结果：**得到可点击、可滚动、可追溯到模拟数据来源的中文经营看板。

## Prompt 6｜把重复流程封装成 Skill

```text
请调用 Superpowers 的 writing-skills Skill；如果本机同时有 $skill-creator，也请一并使用。把当前“月度经营复盘”流程封装为一个可复用 Skill，名称为 monthly-business-review。

先在当前 workspace 的 output/monthly-business-review/ 中生成草稿，不要覆盖已有 Skill，也不要直接安装到全局目录。

Skill 必须包含：
1. 输入文件发现与必需字段检查。
2. 经营指标、预算差异、合同、税务、采购五类分析步骤。
3. 数字勾稽规则：毛利额 - 期间费用 = 经营利润；预算差异可回算；采购明细可加总。
4. 并行 Subagents 的任务边界与统一输出 schema。
5. 管理层汇报模板、来源引用、缺失信息处理规则。
6. timeout、错误处理、日志和人工复核 gate。
7. 至少 3 个 test cases：标准数据、缺失文件、数字冲突。

完成后：
- 展示 Skill 目录树和 SKILL.md 摘要；
- 用当前模拟数据跑一次 dry run；
- 报告测试结果和仍需人工确认的风险；
- 最后给出“如何安装到个人 Skills 目录”的步骤，但等我确认后再安装。
```

**预期结果：**得到可审阅、可测试的 Skill 草稿，而不只是一个超长 prompt。

```text

文档标题：Codex 培训｜2026 年 6 月经营复盘（模拟）

要求：
1. 保留标题层级、表格和行动清单，首段明确标注“虚构培训数据”。
2. 不覆盖或修改任何现有文档。
3. 创建成功后返回文档标题、URL 和写入的章节数。
4. 再读取刚创建的文档，核对“一页结论”和“需要管理层决策”两节是否存在。
5. 如果飞书未授权或 Skill 不可用，准确报告阻塞点，不要声称已创建。
```

## Prompt 9｜飞书 Base：创建并导入行动台账

```text
请调用 $lark-base Skill，读取当前 workspace 的 07-feishu-base.json，并新建一个飞书多维表格。

多维表格名称：Codex 培训｜2026 年 6 月经营复盘行动台账（模拟）

要求：
1. 按 JSON 中的 fields 创建字段，按 records 一次性导入全部记录。
2. 不写入任何已有 Base，不修改现有字段或记录。
3. 导入后重新读取记录总数，并按所属团队统计数量。
4. 校验金额字段是 number 类型、截止日期是 date 类型、优先级和状态是 single_select。
5. 返回 Base URL、table 名称、成功记录数、失败记录及原因。
6. 如果操作涉及额外授权，先说明需要的权限，授权完成后继续。
```

```text
请按以下结构输出：

```

## 安全边界

- 优先从公司 Skill 市场安装；访问 GitHub 前确认网络条件。
- 第三方 Skill 安装前检查来源、最近维护时间、脚本内容、所需权限和写入范围。
- 任何 Skill 都不得读取 API key、Token、个人账号或 workspace 外的机密文件。
- 飞书写操作仅作用于本次新建的培训文档和 Base；不覆盖现有业务数据。
- Agent 输出是分析草稿，关键数字、合同判断、税务判断和对外发送内容必须人工复核。
